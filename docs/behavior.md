# Behaviour specification

> Last reviewed: 2026-11-25 · Version 0.2.1

This is the contract the app implements and the clean-room specification agents
may use. Code, labels and assets are AntiRustPaste's own; no CopyClip source or
assets are used.

## 1. Lifecycle

- AntiRustPaste launches as a menu-bar accessory (`LSUIElement`, activation policy
  `.accessory`). It has no Dock icon and no main window at startup.
- A highlighter-and-check template icon appears in the status bar.
- Left-click the symbol: toggle the history popup.
- Right-click the symbol: show the status menu.
- Quit from the status menu. History is already saved on every change.

## 2. Capture

The app polls the general pasteboard every 1 s and reacts when `changeCount`
changes.

Captured kinds and precedence within one pasteboard item:

1. `public.file-url` → File. The stored text is the decoded POSIX path; the
   list shows the file name.
2. `public.png` / `public.tiff` / `public.jpeg` → Image. Bytes are stored
   verbatim with the UTI, and the dimensions are read with the pure-Rust imaging
   crate. The Images tab shows a thumbnail and `Image · W×H · <size>`.
3. `public.rtfd` / `public.rtf` / `public.html` → Rich Text or HTML. The bytes
   are stored with the UTI and the plain-text representation is kept as a
   fallback; the list shows the plain text when available.
4. `public.utf8-plain-text` / `public.plain-text` / `NSStringPboardType` → Text.
   Whitespace-only text is skipped.

Rules:

- A pasteboard change carrying `org.nspasteboard.ConcealedType` or
  `org.nspasteboard.TransientType` is ignored entirely.
- At most 25 items are read from one change.
- One blob may be at most 50 MiB; larger or empty data is skipped.
- If recording is disabled, changes update the internal counter but are not
  inserted. Re-enabling recording starts from the then-current change count.
- A change whose source app is in the ignored list is skipped. The source is the
  last frontmost application that was not AntiRustPaste at poll time.
- Duplicate content (same kind, text, data type and bytes) is not appended.
  The existing entry moves to the top.
- The history is trimmed to the configured maximum (default 200, range 1–9999).

## 3. History list and tabs

The popup has two tabs, selected by a segmented control or ⌘1/⌘2:

- **Text** — text, rich text, HTML and file URL clippings. Each row shows a
  coloured kind dot, a one-line truncated preview and a subtitle
  `<source app> · <relative time>`.
- **Images** — bitmap clips only. Each row shows a 40 pt thumbnail (from the
  temporary cache), `Image · W×H · <size>` and the same subtitle. Thumbnails are
  generated by a background worker: the first draw may show an `IMG` placeholder
  for a moment. A clip whose thumbnail cannot be generated keeps the placeholder.
- Space on the Images tab (with an empty search field) or `⌘Y` opens the
  selected image in the shared Quick Look panel, like Finder. Space or Esc
  closes the preview and returns focus to the popup. The full-size blob is
  written to a private file under `<thumbnail cache>/previews/` for the panel
  and deleted when the preview closes; a missing or unreadable blob only beeps.

Both tabs are newest first, except pinned clips: they form a group at the top
(first pinned row newest), separated from the rest of the list by a **PINNED**
header and a rounded card, and show a filled accent pin. When both groups exist
the unpinned rows follow a **RECENT** header; a header is omitted when its group
is empty. Headers scroll with the list and cannot be clicked. Empty tab:
`Your clippings will appear here…` or `Your images will appear here…`. No search
result: `No clippings found` or `No images found`. File URLs stay in Text even
when they point at an image.
- The footer shows `N clipping(s)` / `N image(s)` and two buttons: **Clear
  Text** and **Clear Images**. Each button clears the whole section, not just
  search results; it is disabled when that section is empty. On the Images tab
  a **PDF…** button appears between the count and **Clear Text**; the footer
  hint reads `⌘E PDF` there instead of `⌘P pin`.
- The list scrolls with the wheel/trackpad and clamps to its content. Drawing
  stops at the list edges, so rows and the pinned card never cover the search
  field or the footer.
- Relative time: `just now`, `Nm ago`, `Nh ago`, `Nd ago`, then `Mon D`.
- Preview normalisation: runs of whitespace collapse to one space, leading and
  trailing whitespace is removed, and the preview stops at 160 characters.

## 4. Search

- Typing filters within the active tab on the preview, the full text (for
  text/rich/file clips) and the display title, case-insensitively.
- Filtering is live; the selection resets to the first row and scroll resets.
- Clearing the field restores the full tab.
- The placeholder reads `Search clippings` or `Search images`.

## 5. Keyboard

| Key | Behaviour |
| --- | --- |
| ↑ / ↓ | Move selection one row |
| Home / End | Move to first / last row |
| Return / keypad Enter | Paste the selected clipping |
| ⌘C | Write the selected clipping to the clipboard, no synthetic paste |
| Delete / Forward Delete | Delete the selection when the search field is empty or ⌘ is held |
| Escape | Close the popup |
| ⌘1 / ⌘2 | Switch to the Text / Images tab |
| ⌘P | Pin or unpin the selected clipping (the row pin icon does the same) |
| Space | On the Images tab with an empty search, open or close the Quick Look preview |
| ⌘Y | Open or close the Quick Look preview of the selected image |
| ⌘E | Open the image export window when the history contains images |
| Tab / typing | Goes to the search field; the list does not steal text input |

Space only opens the preview while the search field is empty, so typing a
space inside a query still inserts it. The key monitor runs before the responder
chain and only acts while the popup is visible and key. It never consumes keys while another window (Preferences) is
key.

## 6. Paste

1. The selected clip is written to the general pasteboard using its best type:
   text as string, file as `public.file-url`, rich/image as the stored UTI, rich
   clips also get a plain-text fallback.
2. The new `changeCount` is recorded so the write is not captured again.
3. The popup hides.
4. The app that was frontmost when the popup opened is activated. If it quit,
   the last non-AntiRustPaste frontmost app is used.
5. On the first paste attempt the app asks for Accessibility trust.
6. After 0.25 s a synthetic ⌘V down/up is posted. Without Accessibility the
   clipboard still contains the clip and the user can paste manually.

## 7. Status menu

- **Preferences…** opens the preferences window.
- **Export Images to PDF…** opens the image selection window; with no images it
  beeps and explains that at least one image is needed.
- **Clear All Clippings** asks for confirmation when enabled, then clears the
  index, every text/image blob and the thumbnail cache (including pending jobs).
- **About AntiRustPaste** shows version, shortcut and history path.
- **Quit AntiRustPaste** terminates the app.

## 8. Export images to PDF

Entry points: the **PDF…** footer button on the Images tab, **Export Images to
PDF…** in the status menu, or `⌘E` while the popup is open. With no images the
app beeps and shows an explanation instead of opening a window.

The export window lists every image clip in history order (pinned first, newest
first). Every image starts selected.

- Clicking a row or its checkbox includes or excludes that image.
- Dragging a row up or down changes the page order; an accent line marks where
  it will land. A press that moves less than 3 pt counts as a click, so dragging
  never toggles the checkbox. The list scrolls when a drag reaches an edge.
- Row order is the PDF page order. It lives only in the open window and resets
  to history order the next time the window opens.
- **Select All** (⌘A) and **Select None** (⌘D) change the whole selection.
- The status line reads `N of M images selected`; **Save PDF…** (⌘S) is disabled
  when nothing is selected.
- **Cancel**, esc or the title-bar close button close the window without saving.
- Images captured while the window is open are appended after the next list
  refresh (a click, drag or selection change) and start unselected.

**Save PDF…** opens the system save dialog with the default name
`Clipboard Images.pdf`; a missing `.pdf` extension is added. After a destination
is chosen the app:

1. reads the original blobs (not thumbnails) for the selected images;
2. builds one A4 page per image in the order shown in the window, centring each
   image with a 12 mm margin and preserving its aspect ratio; an image larger
   than the printable area is scaled down to fit, a smaller one keeps its
   native size (1 pixel = 1 point);
3. decodes each image to 8-bit RGB, compositing transparency onto white, and
   compresses the samples with Flate;
4. writes the complete PDF to a temporary file next to the destination and
   renames it into place.

Cancelling the save dialog writes nothing. A missing or unreadable blob aborts
the export with an alert and no file; a write or rename failure is reported the
same way. The export never changes history, pins, settings or thumbnails.

Limitations in this version: no page-size/orientation options, no progress
indicator (encoding runs on the main thread after the dialog closes), and EXIF
orientation is not applied. Large selections pause the popup until the file is
written.

## 9. Preferences

### General

- **Remember last N clippings** — integer 1–9999. Reducing below the current
  count asks for confirmation when confirmations are on, then trims the oldest.
  Invalid input reverts to the previous value.
- **Record clipboard history** — when off, no new clips are stored.
- **Confirm before deleting** — gates row deletion, clear-all and limit
  reduction.
- **Start AntiRustPaste at login** — writes/removes the LaunchAgent plist. Failure
  restores the switch and shows an alert.
- **Global shortcut** — click the button, then press a combination with at least
  Command, Option or Control. Escape cancels. The old shortcut is suspended while
  recording, restored on cancel or failure. Bare letters are beeped and ignored.
  A shortcut in use by the system or another app shows an alert.
- **Clear Thumbnail Cache** — deletes the existing preview files and queues a
  cleanup for in-flight jobs, then clears the in-memory thumbnail cache. The
  history is untouched; visible images regenerate in the background on the next
  draw.

**Clear Text** removes text, rich text, HTML and file clippings. **Clear Images**
removes image clippings and their thumbnails. Both include pinned clips in their
section, respect *Confirm before deleting*, keep the other section, and cannot
be undone. The status menu's
**Clear All Clippings** still removes everything, including the thumbnail cache.

### Exceptions

- Lists ignored apps as `Name — bundle.id`, scrollable.
- **Add App…** opens an application chooser and stores the bundle identifier.
  Items without a bundle id are rejected.
- **Remove** deletes the selected entry.
- Duplicate bundle ids are not added twice; entries sort by lowercased name.
- Ignoring affects new captures only; existing history is not purged.

## 10. Storage behaviour

On the first launch of 0.2.0 the old `Application Support/RustClip` directory is
renamed to `Application Support/AntiRustPaste` when the new directory does not
exist yet. If the rename fails, both are left untouched and the app starts with
an empty new history rather than deleting anything.

- History: JSON index + blob files, atomic index replacement.
- A corrupt index becomes `history.json.bak`; the app starts empty and logs.
- Missing blob files drop their records on load.
- Deleting/trimming/clearing removes the corresponding blobs and cached
  thumbnails.
- `pinned` is a boolean on each `Clip` (default `false` for old histories).
  Pinned clips stay above unpinned clips and are exempt from automatic trimming;
  the configured maximum applies to unpinned clips. Re-copying a pinned clip
  keeps it pinned. Explicit delete/section clear/clear-all removes pinned clips.
- Thumbnails live outside the history, in `ANTIRUSTPASTE_THUMB_CACHE_DIR` or, by
  default on macOS, `/tmp/AntiRustPaste-<user>-<hash>/thumbnails`. macOS clears
  `/tmp` at boot; the **Clear Thumbnail Cache** button deletes existing previews
  immediately and queues cleanup for in-flight jobs.
- Preferences use `NSUserDefaults`.
- Login item: `~/Library/LaunchAgents/com.rustclip.app.plist`.

## 11. Edge cases

- Empty pasteboard or an unsupported-only item: no history change.
- Several pasteboard items: each supported item is captured in order, up to 25.
- Re-copying a history item moves it to the top; its old blob is replaced.
- A very long text clip: preview truncated, full text kept.
- A malformed/oversized history or blob: handled without a crash (see
  `docs/testing.md`).
- An image too large or corrupt: the clip is still stored/pasteable, the Images
  row shows a placeholder, and no thumbnail is cached.
- A missing/corrupt thumbnail file: regenerated in the background from the
  original blob.
- A read-only or unwritable cache directory: the row keeps the `IMG` placeholder;
  the history is unaffected.
- Two app instances: not supported. The second instance can fail to register the
  hot key. Each process keeps its own in-memory copy and writes atomically, so
  the JSON is not structurally corrupted, but the last writer can overwrite the
  other instance's newest clips.
- Global shortcut conflict: recording fails with an alert; the previous shortcut
  is restored.
- Accessibility denied: manual paste still works.

## 12. Non-goals

Cloud sync, named clipboards, encryption at rest, an image grid, EXIF
orientation correction, per-row accessibility elements (currently absent),
automatic updates, and copying CopyClip's visual identity.
